# 글쓰기 우선 개인 홈페이지 기획서

작성일: 2026-09-27  
프로젝트: `writer-first-homepage`

## 1. 문제와 목표

기존 `what-i-think`는 Markdown과 CMS 폼을 중심으로 구성되어 이미지 삽입, 문단 줄바꿈, 발행 전 화면 확인이 끊겼다. 새 홈페이지는 “글을 쓰는 순간에 보이는 결과물”을 중심으로 만든다. 작성자는 별도 문법을 학습하지 않고도 사진과 문장을 배치하고, 독자는 빠르고 편안하게 읽는다.

### 완료 상태

1. 글 작성 화면에서 문단·제목·인용·목록·링크·글꼴·정렬을 바로 적용한다.
2. 사진을 파일 선택, 드래그 앤 드롭, 붙여넣기로 넣고, 선택 후 작은/본문 폭/와이드/직접 폭 조절을 한다.
3. 작성 화면의 본문 폭과 읽기 화면의 본문 폭을 일치시켜 발행 전 결과를 예측할 수 있다.
4. 메뉴를 계층 구조로 추가·이름 변경·순서 이동·들여쓰기·내어쓰기 한다.
5. 각 공개 글을 검색엔진과 AI 검색이 이해할 수 있는 독립 URL과 HTML로 발행한다.

## 2. 사용자와 핵심 여정

주 사용자는 한 명의 기록자다. PC에서 긴 글과 사진을 작성하고, 모바일에서 짧은 기록을 보완하거나 읽는다.

### 글쓰기 여정

1. 스튜디오에서 `새 글`을 누른다.
2. 제목을 쓰고 본문을 바로 입력한다. Enter는 새 문단, Shift+Enter는 같은 문단 안 줄바꿈이다.
3. `/` 또는 플러스 버튼으로 사진·제목·인용·구분선을 넣는다.
4. 사진을 누르면 크기와 정렬만 담은 작은 맥락 도구 막대가 나타난다.
5. 오른쪽 미리보기 또는 모바일 전환으로 실제 독자 화면을 확인한다.
6. 카테고리·태그·요약·대표 사진을 최소 입력 후 임시저장 또는 발행한다.

### 메뉴 관리 여정

1. 스튜디오의 `메뉴`에서 메뉴 항목을 본다.
2. 항목을 드래그해 순서를 바꾸거나 오른쪽으로 들여쓰기해 하위 메뉴로 만든다.
3. 메뉴 이름과 연결 경로를 바꾸고 저장한다.

## 3. 정보 구조

| 표기 | URL 기본값 | 기록 성격 |
| --- | --- | --- |
| 발자취 | `/milestones` | 날짜와 한 줄 성취를 빠르게 남기는 타임라인 |
| 비즈로그 | `/business` | 사업 계획, 실행, 회고 |
| 에세이 | `/essays` | 생각, 인사이트, 푸념 |
| 일상 | `/life` | 사진 중심의 독서·여행·일상 |
| 지식 | `/library` | 다시 찾는 지식과 자료 |

메뉴 데이터는 `id`, `label`, `href`, `parentId`, `order`, `visible`을 가진 트리로 관리한다. 상단에는 한 단계만 펼치되, 스튜디오에서는 깊이 제한 없이 편집할 수 있다.

## 4. 편집기 설계

### 네이버 SmartEditor ONE에서 가져올 원칙

- 기본 도구와 선택 도구를 분리한다. 평소에는 단순한 도구막대, 사진을 선택했을 때만 크기·정렬·캡션 도구를 보여준다.
- 사진·글·구분선을 블록 단위로 취급해 순서 이동이 자연스럽게 한다.
- PC와 모바일에서 같은 초안과 서식을 보여준다.
- 태그는 입력 후 Enter로 칩 형태가 되며 삭제는 한 번의 동작으로 끝난다.

### 반드시 지원할 동작

- 제목 1·2·3, 본문, 인용, 코드, 순서/비순서 목록, 링크, 구분선
- 굵게, 기울임, 밑줄, 취소선, 글꼴, 크기, 색, 정렬
- 붙여넣은 서식 정리, Enter/Shift+Enter 구분, 되돌리기/다시하기
- 이미지 파일 선택, 드롭, 클립보드 붙여넣기
- 작은/본문 폭/와이드/사용자 폭 이미지와 좌·가운데·우 정렬, 대체 텍스트·캡션
- 자동 임시저장, 발행 전 미리보기, 데스크톱·모바일 전환

### 기술 결정

블록형 리치 텍스트 엔진으로 Tiptap/ProseMirror 계열을 사용한다. HTML을 단순 텍스트로 저장하지 않고 편집 가능한 JSON 문서와 렌더된 HTML을 함께 관리한다. 이미지 업로드는 발행 환경에서 오브젝트 스토리지 또는 GitHub 미디어 경로로 바꿔 연결할 수 있게 추상화한다. 초기 구현은 브라우저 저장소에서 초안과 메뉴의 전체 편집 흐름을 검증한다.

## 5. 디자인 콘셉트

### 방향: 조용한 편집실 (Quiet Editorial Desk)

종이의 여백과 신문 편집의 명료함을 활용하는 밝은 편집형 화면이다. 화려한 카드나 장식으로 글보다 UI를 앞세우지 않는다. 독자가 기억할 한 가지는 “여기서는 생각이 정돈되어 있다”이다.

- 본문 서체: `Noto Serif KR`로 긴 글의 리듬을 만든다.
- UI·제목 서체: `Pretendard`로 한글 인터페이스의 가독성을 보장한다.
- 색: 따뜻한 종이색 `#F7F5F0`, 잉크 `#17202A`, 기록을 표시하는 녹청색 `#0E6B63`, 작은 강조의 테라코타 `#BA5A3A`.
- 레이아웃: 읽기 화면은 720px 본문 폭, 작성 화면은 중앙의 동일한 본문 캔버스와 보조 패널로 구성한다.
- 모션: 저장·발행 상태를 150~200ms로만 전환한다. 글 읽기에는 장식 애니메이션을 넣지 않는다.

## 6. 벤치마킹 및 차별점

- [Maggie Appleton](https://maggieappleton.com/)은 에세이와 디지털 가든을 구분해 “완성 글”과 “자라는 메모”의 성격을 드러낸다. 본 프로젝트는 다섯 기록 공간을 같은 글쓰기 도구 안에서 관리하되, 각 공간의 이유를 명확히 표시한다.
- [Derek Sivers](https://sive.rs/) 사례는 장식보다 글 목록과 명확한 이동이 개인 사이트의 신뢰를 만든다는 점을 보여준다. 홈 화면은 과도한 히어로 대신 최근 기록과 메뉴 진입을 우선한다.
- 네이버 SmartEditor ONE은 사진 선택 시 즉시 크기 선택과 수치 입력을 제공하고, 사진·텍스트를 끌어 놓아 재배치하는 편집 흐름을 제공한다. 새 편집기는 이 맥락형 조작을 우선 구현한다. [사진 크기 조절](https://help.naver.com/service/5593/contents/15467?lang=ko&osType=PC), [에디터 소개](https://help.naver.com/service/5593/contents/15506?lang=ko&osType=COMMONOS)

## 7. SEO와 AI 검색 친화성

### 구현 항목

- 서버 또는 빌드 시 렌더되는 HTML, 사람이 읽는 제목/H1/문단, 고유한 URL과 canonical URL
- 게시물별 `title`, `description`, Open Graph, `Article` JSON-LD, 사이트 `WebSite`/`Person` JSON-LD
- `sitemap.xml`, `robots.txt`, RSS, 내부 링크, 이미지 `alt`와 캡션
- 모바일 성능, 이미지의 크기 속성 및 지연 로딩, Search Console 연결 지점
- `robots.txt`에서 Googlebot과 `OAI-SearchBot`을 의도적으로 허용하고 CDN/WAF도 같은 정책을 적용

### 사실과 한계

Google AI Overviews/AI Mode에는 별도 AI용 마크업이 필요하지 않다. 일반 검색 색인 대상이 되는, 공개된 고유 콘텐츠·텍스트·내부 링크·좋은 페이지 경험이 기준이다. 구조화 데이터는 보이는 내용과 일치해야 하며 노출을 보장하지 않는다. [Google AI 기능 가이드](https://developers.google.com/search/docs/appearance/ai-features), [Google 생성형 AI 검색 가이드](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide), [구조화 데이터 안내](https://developers.google.com/search/docs/appearance/structured-data/intro-structured-data)

ChatGPT 검색은 공개 사이트가 후보가 될 수 있으나 순위나 추천 노출은 보장되지 않는다. 본문 요약과 인용에 포함되려면 `OAI-SearchBot`을 차단하지 않아야 하며, 학습 크롤러인 `GPTBot` 허용 여부와는 독립적으로 제어할 수 있다. [OpenAI 게시자 FAQ](https://help.openai.com/en/articles/12627856-publishers-and-developers-faq), [OpenAI 크롤러 문서](https://developers.openai.com/api/docs/bots)

따라서 “AI에 들어가게 하는 기능”은 별도로 약속하지 않고, 검색 가능한 공개 원문과 기술적 접근성을 제품 기능으로 보장한다.

## 8. 단계와 검증

1. 기획서·화면정의서: 작성 흐름과 화면의 역할을 고정한다.
2. 스튜디오: 리치 텍스트, 이미지 조작, 자동 저장, 미리보기를 구현한다.
3. 공개 사이트: 홈·카테고리·글 상세·메뉴 트리를 구현한다.
4. 검색: 메타데이터, JSON-LD, sitemap, robots, RSS를 구현한다.
5. 검증: 이미지 삽입·크기·줄바꿈·모바일·SEO 산출물·키보드 동작을 점검한다.
